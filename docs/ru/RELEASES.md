# Подготовка релиза

## Задача
Подготовить два разных артефакта:

- самостоятельный бинарник под Windows: `tunnellio.exe`;
- универсальный архив исходников: `tunnellio-source-v<версия>.zip`.

Бинарник привязан к Windows. Архив исходников от системы не зависит и содержит файлы Python-проекта.

## Правило для архива исходников
Универсальный архив собирается из **состояния, которое отслеживает git**, а не из списка файлов, поддерживаемого руками.

Это значит:

- архив соответствует конкретной ревизии git;
- содержимое архива совпадает с тем, что действительно версионируется;
- локальные неотслеживаемые файлы в релиз не попадают.

## Шаг 1. Собрать бинарник
```powershell
.\scripts\build_windows_binary.ps1
```

## Шаг 2. Собрать архив исходников из git
```powershell
.\scripts\build_release_archive.ps1
```

Можно указать ревизию явно:
```powershell
.\scripts\build_release_archive.ps1 -Ref HEAD
.\scripts\build_release_archive.ps1 -Ref v0.1.5
```

## Что получается
- папка подготовки под Windows: `artifacts\tunnellio-windows-x64-v<версия>\`;
- универсальный архив: `artifacts\tunnellio-source-v<версия>.zip`.

## Как собирается архив
Скрипт берёт состояние git, а не ручной список включаемых файлов. По умолчанию архивируется `HEAD`. Так архив соответствует ровно той ревизии репозитория, которую выпускают.

## Что попадает в архив
Всё, что отслеживается git на выбранной ревизии и принадлежит ей. Бинарник под Windows в архив исходников **не** попадает.

## Что попадает в локальную папку релиза
- `tunnellio.exe`
- `tunnellio-source-v<версия>.zip`
- `GITHUB_RELEASE.md`

## Что написать в описании релиза
Сказать прямо:

- `tunnellio.exe` — готовый бинарник под Windows;
- `tunnellio-source-v<версия>.zip` — универсальная поставка с исходниками;
- архив исходников работает и вне Windows, с обычными требованиями к Python, OpenSSH и окружению.
