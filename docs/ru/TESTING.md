# Проверки

## Быстрая проверка исходников
Самое дешёвое, что стоит делать перед каждым коммитом: убедиться, что всё компилируется.

```powershell
python -m compileall src tests
```

## Локальный набор тестов
В проекте нет установленного раннера: тесты вызываются напрямую, чтобы набор работал на голой машине без лишних зависимостей. Полная команда со списком всех проверок лежит в английском варианте этого документа, `docs/TESTING.md`, и дублировать её здесь целиком незачем: список меняется, а два списка в двух файлах разойдутся в первый же день.

Смысл набора по частям:

- `tests/test_client.py` — построение контекста TLS, в том числе через системное хранилище Windows; обнаружение OAuth; обмен и интроспекция токена; открытие сессии, heartbeat и закрытие с resume-токеном;
- `tests/test_planner.py` — разбор селектора домена, сборка тела запроса на запуск, требование ключа для чужого домена, контракты сессии и авторизации в плане;
- `tests/test_oauth.py` — пара PKCE, сборка адреса авторизации, запись токена и её чтение с диска, сохранение старого refresh-токена, если сервер не прислал новый;
- `tests/test_cli.py` — разбор аргументов, необязательность флагов, фильтрация по имени, порядок обновления конфига по умолчанию, снимок параметров подключения;
- `tests/test_config.py` — шаблон конфига запуска, подстановка значений по умолчанию, запись пути конфига в метаданные.

## Дымовая проверка командой
После сборки имеет смысл прогнать сам бинарник: разобрать аргументы, показать план, поднять туннель на тестовый порт и остановить его по имени.

```powershell
python -m tunnellio.cli --help
python -m tunnellio.cli status
```

## Локальный сквозной прогон
```powershell
.\run_local_e2e.ps1
```

Что он проверяет и что для него нужно, описано в `LOCAL_E2E_TESTS.md` в корне проекта.

## Правило
Перед выпуском версии прогоняются все три уровня: компиляция, локальный набор и сквозной прогон. Пропуск последнего допустим только тогда, когда изменения не касаются запуска туннеля вовсе.
