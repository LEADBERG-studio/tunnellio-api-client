# Эксплуатация

## Голый SSH и клиент
Голый SSH умеет одно: поднять обратный туннель. Клиент добавляет к этому:

- обнаружение возможностей через API;
- планирование запуска с учётом того, что разрешено учётной записи;
- согласование ключа, домена и сессии;
- проверку TLS системным хранилищем Windows через `truststore`;
- структурированные журналы;
- реестр запусков;
- вывод состояния;
- запуск SSH через `connect --run`;
- присмотр и перезапуск через `connect --run --watch`;
- остановку и перечисление управляемых запусков;
- имена запусков, по которым туннелем можно управлять адресно;
- снимки runtime-конфига, доступные по имени;
- запуск от конфига как основной способ работы;
- корректное завершение эфемерной сессии;
- жизненный цикл сессии: открытие, heartbeat, возобновление, закрытие;
- учёт resume-токена при heartbeat, закрытии и возобновлении.

## Транспорт
Сам туннель по-прежнему создаётся системным `ssh` с обратным пробросом. Клиент не подменяет транспорт SSH, он им управляет. Отдельно есть TCP-мост, у него свой документ.

## Имена запусков
У каждого управляемого туннеля есть имя.

- Если передан `--name`, используется он.
- Если `--name` не передан, клиент сам порождает устойчивое имя для этого запуска.

Дальше имя видно в реестре и используется в `status --name`, `stop --name` и `show-config --name`.

## Зачем это нужно в эксплуатации
Адресное управление — не удобство, а необходимость, когда:

- на машине больше одного туннеля;
- туннель поднимает другая программа;
- домен случайный или эфемерный;
- вызывающей стороне нужно узнать итоговый серверный адрес уже после запуска.

В этих случаях имя становится устойчивым локальным идентификатором, а `show-config --name` — местом передачи данных между клиентом и вызывающей программой.

## Рекомендованный боевой запуск
### Запомнить параметры
```powershell
.\tunnellio.exe --token ВАШ_ТОКЕН connect --domain existing:mcp --local-port 3000 --run --watch --name prod-api --health-path / --log-file .\logs\tunnel.log
```

### Дальше запускать без аргументов
```powershell
.\tunnellio.exe
```

### Посмотреть все имена
```powershell
.\tunnellio.exe status
```

### Посмотреть один туннель
```powershell
.\tunnellio.exe status --name prod-api
```

### Остановить один туннель
```powershell
.\tunnellio.exe stop --name prod-api
```

### Забрать параметры подключения
```powershell
.\tunnellio.exe show-config --name prod-api
```

## Реестр запусков
Даже если `--status-file` и `--stop-file` не переданы, клиент создаёт файлы управляемых запусков сам:

- `~/.tunnellio/state/runtimes/*.json`
- `~/.tunnellio/state/runtimes/*.config.json`
- `~/.tunnellio/state/runtimes/*.stop`

Это и есть устойчивый локальный реестр работающих и недавно работавших туннелей.
