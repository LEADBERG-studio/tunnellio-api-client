# Контракт для вызывающей программы

## Зачем это нужно
Клиент — не только программа для человека в терминале. Это ещё и локальный слой управления, к которому обращается другая программа.

Особенно это важно, когда туннель поднимается:

- на случайно выбранном домене;
- на эфемерном имени;
- с порождённым именем запуска.

В этих случаях вызывающая программа не может знать итоговый публичный адрес заранее. Она должна уметь:

1. запустить туннель;
2. опознать его по имени;
3. прочитать итоговые серверные параметры подключения;
4. дальше управлять тем же туннелем по тому же имени.

## Учётные данные и доступные режимы (0.6.0)

API-токен — самое полное удостоверение, но не обязательное. Вызывающая программа может выбрать режим по тому, что у оператора реально есть.

| Что есть | Доступные режимы |
| --- | --- |
| API-токен | всё: полный поток через API, `ssh_stable`, `tcp_stable`, `tcp_random` |
| только SSH-ключ | `ssh_stable`, `tcp_stable`, `tcp_random` |
| ничего | `tcp_stable`, `tcp_random` |

- `ssh_stable` — прямой обратный проброс по SSH на заранее закреплённый домен вашим ключом. Команда собирается локально, обращений к API нет.
- `tcp_stable` — TCP-мост без ключей на закреплённый домен.
- `tcp_random` — TCP-мост без ключей на домен, который выдаёт сервер.

В этих трёх режимах API-токен не читается и не проверяется, даже если он настроен. Токен по-прежнему нужен там, где реально работает Integration API: создание домена или ключа, облачный маршрут, OAuth, `--transport auto`.

```powershell
# Вообще без учётных данных
.\tunnellio.exe connect --transport tcp-bridge --domain random --local-port 3000 --run

# Свой домен, по-прежнему без API-токена
.\tunnellio.exe connect --transport tcp-bridge --domain existing:mcp --local-port 3000 --run

# Свой домен и свой SSH-ключ, по-прежнему без API-токена
.\tunnellio.exe connect --transport ssh --domain existing:mcp --local-port 3000 --run
```

Проверка из кода:

```python
from tunnellio.modes import available_modes, resolve_mode

available_modes(has_api_token=False, has_ssh_key=True)
# ('ssh_stable', 'tcp_stable', 'tcp_random')

resolve_mode(command='connect', transport='ssh', domain_selector='existing:mcp')
# ModeDecision(mode='ssh_stable', requires_api_token=False, ...)
```

## Ограничение тарифа — не отказ в доступе

`POST /v1/meta` и `POST /v1/capabilities` носят справочный характер. На части тарифов сервер отвечает `403 plan_required`. С версии 0.6.0 это порождает `PlanRequiredError`, а не `AuthError`, и запуск продолжается. Всё, что оказалось недоступно, перечислено в поле `degraded`:

```json
{
  "ok": true,
  "degraded": ["meta unavailable on this plan: ..."]
}
```

Когда возможности неизвестны, клиент перестаёт угадывать за сервер, что учётной записи можно. Источник истины — сервер, и он откажет сам, если что-то не разрешено.

## Что гарантируется
Для каждого управляемого туннеля клиент обещает:

- имя запуска существует всегда;
- имя может быть задано явно или порождено;
- состояние запуска хранится локально;
- снимок параметров подключения хранится локально;
- по тому же имени можно посмотреть состояние, остановить туннель и забрать параметры подключения.

## Правила именования
### Явное имя
Если передан `--name prod-api`, именем запуска будет `prod-api`.

### Порождённое имя
Если `--name` не передан, клиент порождает имя сам. Оно такой же полноценный идентификатор, и обращаться с ним нужно так же, как с заданным вручную.

## Рекомендованный порядок для программы
### Шаг 1. Поднять туннель
```powershell
.\tunnellio.exe --token ВАШ_ТОКЕН connect --domain random --key existing:mcp --local-port 3000 --run --watch
```

Если нужен предсказуемый идентификатор, лучше передать имя явно:
```powershell
.\tunnellio.exe --token ВАШ_ТОКЕН connect --domain random --key existing:mcp --local-port 3000 --run --watch --name app-backend
```

### Шаг 2. Узнать имя, если оно порождено
Его можно взять из вывода запуска, из `status` или из файлов реестра. Для автоматизации настоятельно рекомендуется всё же передавать `--name`.

### Шаг 3. Спросить состояние по имени
```powershell
.\tunnellio.exe status --name app-backend
```

### Шаг 4. Забрать итоговые параметры подключения
```powershell
.\tunnellio.exe show-config --name app-backend
```

Возвращается снимок в JSON, в нём:

- метаданные запуска;
- `launchConfig`;
- `connection`;
- пути к файлам состояния и остановки;
- поля контракта авторизации: `authMode`, адрес обнаружения, адрес метаданных защищённого ресурса, адреса токена, авторизации и интроспекции, режим проверки токена, поддерживаемые области и способы передачи токена;
- идентификаторы сессии и запуска: `sessionId`, `resumeToken`, `proxySessionId`, имя запуска.

Возвращённый контракт следует считать окончательным. Если программа просила один режим, а сервер согласовал другой, верным считается ответ сервера.
